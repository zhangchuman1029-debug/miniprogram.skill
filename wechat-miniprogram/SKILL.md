# 微信小程序开发

把用户目标转译为能在微信开发者工具和目标微信客户端运行的小程序代码。遵循已有项目的技术栈、目录和构建约定；新项目按官方原生结构建立。官方文档和基础库会持续更新，具体接口、属性、最低版本、权限和审核规则必须以 [官方文档索引](references/official-docs.md) 中的当前页面为准，不凭记忆臆造参数。

## 总体流程

1. **识别项目和目标**：检查 `project.config.json`、`miniprogram/`、`app.js`、`app.json`、页面、组件、构建脚本、云开发/云托管目录和请求封装。
2. **选择文档类目**：按下方“类目路由”确定要读的官方入口；跨领域任务同时读取相关类目。
3. **确认运行矩阵**：微信客户端平台、开发者工具、最低基础库、是否使用 Skyline/`glass-easel`、是否支持 PC/企业微信/硬件/XR，以及是否需要登录、授权或网络域名。
4. **设计边界**：先确定页面、组件、数据流、服务端职责和失败状态，再写 WXML、WXSS、JavaScript/TypeScript。
5. **实现与检查**：检查路径、配置、事件、`setData`、生命周期清理、权限、网络、鉴权、包体积和平台差异。
6. **验证并报告**：运行项目已有的 lint、构建和测试；可用时使用开发者工具和真机验证。无法真机验证时必须明确说明。

- **请求、上传、下载、WebSocket、存储、媒体**：基础能力和 API 参考；涉及后台则同时读服务端 API。

- **蓝牙、NFC、Wi-Fi、设备连接或硬件框架**：连接硬件能力和对应平台限制。

- **健康/未成年人/内容和运营合规**：健康运营指引、安全指引和当前平台规则。

- **企业微信内运行**：企业微信兼容文档，以及运行时、组件和开放能力差异。

- **Windows/Mac/PC 展示和交互**：PC 小程序、运行环境和组件差异。

## 项目结构与配置

原生项目通常包含：

- `app.js`：全局逻辑和生命周期。
- `app.json`：页面、窗口、tabBar、网络超时、分包、插件、全局组件/框架和渲染相关配置。
- `app.wxss`：可选的全局样式。
- `pages/<name>/`：同名 `js`、`wxml`、`json`、`wxss`。
- `components/<name>/`：同名 `js`、`wxml`、`json`、`wxss`，组件 JSON 通常声明 `"component": true`。
- `sitemap.json`：涉及小程序搜索时检查。
- `project.config.json`：开发者工具项目设置，不能把本地绝对路径、账号信息或密钥误提交。
- 云开发、云托管、插件、XR 或硬件专用目录：按对应官方类目和项目现状处理。

新增或移动页面后，必须同步维护 `app.json.pages` 和页面同名文件。页面配置覆盖 `app.json.window` 中的同名项。不要凭空添加未知配置字段；先读取配置参考和最低基础库。

## MINA、运行时与数据流

- 逻辑层、视图层和数据/事件传输是小程序框架的基本边界；使用 `Page` 注册页面、`Component` 注册组件。
- 用数据绑定驱动视图，事件处理函数读取 `event.detail` 和 `event.currentTarget.dataset`，校验后以最小数据路径调用 `setData`。
- 页面和组件生命周期中创建的定时器、监听器、Socket、观察者和异步任务必须在离开/销毁时清理，并防止销毁后的回调更新页面。
- 页面跳转使用小程序路由 API：普通跳转、重定向、返回、切换 tab 和重启；不要用 DOM 或浏览器 History API 代替。
- 基础库由用户微信客户端决定；不能假设所有用户使用同一版本。使用新 API、组件、Skyline 或 `glass-easel` 前核对最低版本、兼容性和降级路径。
- 不同 iOS、Android、鸿蒙、Windows、Mac、开发者工具环境可能使用不同脚本/渲染引擎；开发者工具结果不能替代真机验证。

## WXML、WXSS、组件与渲染引擎

- 优先使用官方基础组件；用 `usingComponents` 显式声明自定义组件依赖。
- WXML 使用数据绑定、条件、列表、模板和事件；列表提供稳定的 `wx:key`，避免将会变化的索引作为长期 key。
- 组件以 properties、data、methods、observers、生命周期和自定义事件建立边界；父子通信优先使用属性和事件。
- WXSS 使用小程序支持的选择器、样式能力和尺寸单位；考虑安全区域、字体缩放、长文本、小屏和不同渲染引擎。
- `exparser` 是传统组件框架，`glass-easel` 是新组件框架；旧项目迁移前检查差异、第三方组件和最低基础库。
- WebView 是传统渲染引擎，Skyline 是可选的高性能渲染引擎；Skyline 需要配套的 `glass-easel`，且页面级能力、组件和 WXSS 支持存在差异。
- 只有在性能目标和兼容性矩阵明确时切换 Skyline；为不支持的设备准备 WebView 或功能降级方案。

## 基础能力、网络与服务端

- 使用官方 `wx.*` API 或项目已有封装，检查参数、返回值、状态码、业务码、超时、并发、取消、重试、loading、空状态和失败反馈。
- 网络请求通常要求 HTTPS/WSS、合法服务器域名和有效证书；开发工具的跳过校验只用于临时开发。
- 文件、媒体、地图、位置、存储、设备、Worker、WebView、Socket 等能力都要按对应 API 页面核对权限、平台、大小/并发限制和基础库。
- 服务端 API、云函数和云托管负责身份鉴权、资源归属、价格、角色和敏感业务规则；客户端代码不具备保密性。
- 不把 `AppSecret`、支付密钥、数据库密码或后台加密密钥写入客户端；不要信任用户提交的用户 ID、角色、价格或资源 ID。

## XR、硬件、插件与平台扩展

- **XR-FRAME**：先读 XR-FRAME 的运行环境、场景、资源、相机、交互、性能和平台支持；不要把普通 Web 3D 代码未经验证地当作小程序 XR 代码。
- **硬件连接**：先确定蓝牙/NFC/Wi-Fi/硬件框架和目标平台，再实现发现、连接、权限、状态变化、断开、重连和资源释放。
- **插件**：检查插件声明、版本、组件/API 暴露、宿主小程序限制、用户隐私和发布要求；不要把插件当作可访问宿主全部数据的模块。
- **PC 小程序**：检查窗口、鼠标/键盘、布局、hover、右键、文件和平台 API 差异；不能只按手机触摸交互验收。
- **企业微信**：逐项核对企业微信兼容文档中的登录、能力、组件、域名和版本差异，避免默认等同于微信客户端。

## 开放能力、隐私与安全

- 登录流程通常由小程序取得临时凭证、发送到服务端、服务端换取身份并建立自己的登录态；敏感操作由服务端鉴权。
- 授权遵循最小权限、按需申请和明确用途；处理拒绝、取消、过期、撤回授权、设置页返回和用户数据删除。
- 不用隐藏按钮、隐藏页面或前端条件判断代替后台权限控制，防止平行越权和垂直越权。
- 不明文保存密码、密钥、身份证号、手机号、银行卡号等敏感数据；展示时脱敏，并遵守数据生命周期要求。
- 对分享、支付、订阅、客服、用户信息、位置、相机、麦克风和文件等开放能力，读取官方授权、隐私、平台和审核要求。
- 云开发/云托管也需要鉴权、输入校验、最小权限和日志脱敏；不要因为运行在云端就跳过安全审查。

## 调试、性能、搜索、国际化与运营

- **调试**：使用 Console、vConsole、Source Map、真机调试、实时日志和开发者工具能力定位问题；保留可复现步骤、设备、微信版本、基础库和错误堆栈。
- **性能**：分别分析启动性能和运行时性能；关注首屏、分包、请求、资源、`setData`、长列表、图片、动画、内存和重复渲染。
- **搜索**：涉及收录、页面可发现性、关键词、页面路径和 sitemap 时读取小程序搜索文档，不把 Web SEO 规则直接套用。
- **国际化**：检查语言切换、字体、日期/数字/货币格式、RTL/长文本、时区、图片文字、隐私文案和不同地区网络。
- **健康运营**：上线前检查内容、健康/未成年人、隐私、用户权益、违规处理和平台运营要求；当前规则变化时以官方页面为准。
- **更新日志**：遇到废弃 API、行为变更、迁移、基础库升级或线上回归，读取更新日志并记录迁移影响。

## 验证清单

实现后至少检查：

- JSON 可解析，页面和组件路径真实存在，同名文件齐全。
- WXML 事件、`wx:key`、自定义组件声明和数据路径无误。
- 生命周期清理完成，异步回调不会更新已销毁页面。
- loading、成功、空数据、错误、重试、重复点击和权限拒绝状态完整。
- 网络域名、HTTPS/WSS、证书、超时、并发和服务端鉴权满足上线要求。
- 不同基础库、iOS/Android/鸿蒙、横竖屏、屏幕尺寸和必要的 PC/企业微信环境已验证。
- 新能力满足最低基础库，有明确的降级或阻断策略。
- 分包、包体积、首屏、长列表、图片和内存表现可接受。
- 敏感数据、日志、代码仓库和构建产物没有泄露风险。
- 搜索、国际化、健康运营、隐私和发布要求按需求覆盖。

- 实际运行过的检查/测试及未覆盖的真机、弱网或平台验证。
- 若官方文档与项目现状冲突，保留可运行性，同时记录兼容性风险、迁移方案和后续核验点。
