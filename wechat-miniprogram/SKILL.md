# 微信小程序开发

使用本 skill 时，把用户的目标转译为可在微信开发者工具和微信客户端中运行的小程序代码。遵循项目现有技术栈和目录约定；若项目尚未建立，则按本文件的最小原生结构创建。API、组件属性、基础库兼容性和平台差异可能变化，涉及具体接口时读取 [官方文档索引](references/official-docs.md) 中对应页面，不凭记忆臆造参数。

## 工作方式

1. 先检查项目根目录、`project.config.json`、`app.json`、页面和组件目录，以及是否存在 TypeScript、构建工具、云开发或已有请求封装。
2. 明确运行目标：微信客户端平台、最低基础库、是否使用 Skyline、是否使用 `glass-easel`，以及是否需要真机能力。没有明确要求时保持现有配置，新增能力采用兼容性更好的默认方案。
3. 先建立数据流和页面边界，再实现 WXML、WXSS 和逻辑层。页面是组件的组合，重复交互抽成自定义组件。
4. 实现后检查配置路径、事件绑定、`setData` 数据路径、异步错误处理、网络域名、权限声明和生命周期清理。
5. 使用项目已有的检查、构建或开发者工具流程验证；无法启动微信开发者工具时，至少做静态检查、JSON 解析、路径检查和可运行性审查，并明确未完成的真机验证。

## 项目结构

原生小程序的根目录通常包含：

- `app.js`：全局逻辑和生命周期。
- `app.json`：页面路径、窗口、tabBar、网络超时、分包和全局组件/框架配置。
- `app.wxss`：可选的全局样式。
- `pages/<name>/`：页面的同名 `js`、`wxml`、`json`、`wxss` 文件；页面配置覆盖全局 `window` 中的同名项。
- `components/<name>/`：自定义组件的同名 `js`、`wxml`、`json`、`wxss` 文件；组件 JSON 通常声明 `"component": true` 和 `usingComponents`。
- `utils/`、`services/`、`models/`：仅在项目已有约定或确实能降低复杂度时添加。

不要把服务端密钥、`AppSecret`、支付密钥或其他敏感信息写入会下发到客户端的小程序代码。重要业务规则、身份鉴权和数据权限必须在服务端或云函数执行。

## 框架与数据流

- 逻辑层使用小程序 JavaScript 运行时，视图层使用 WXML 与 WXSS；通过数据绑定和事件系统连接。
- 页面使用 `Page` 注册；组件使用 `Component` 注册。只把需要展示或驱动渲染的数据放入 `data`，避免把大对象、无关缓存或高频临时状态反复传给视图层。
- 视图事件使用 WXML 的事件绑定语法，并在逻辑层定义对应处理函数。事件处理函数中读取 `event`，完成校验后用 `setData` 更新视图状态。
- `setData` 只提交必要的最小数据路径；不要在循环中频繁提交大对象，也不要把不可序列化对象作为页面数据。
- 页面生命周期和组件生命周期中创建的定时器、监听器、连接和任务要在离开页面或组件销毁时清理。
- 页面跳转使用小程序路由 API，按业务选择普通跳转、重定向、返回、切换 tab 或关闭页面；不要用 Web DOM 或浏览器 History API 代替。

## WXML、WXSS 与组件

- 使用基础组件表达结构和交互，优先复用官方组件能力；用 `usingComponents` 显式声明自定义组件依赖。
- WXML 中使用数据绑定、条件渲染、列表渲染、模板和事件；列表必须提供稳定的 `wx:key`，避免使用会随排序变化的索引作为长期 key。
- 不要把用户输入直接拼接为结构、脚本或选择器。展示用户内容时考虑转义、长度限制和空状态。
- WXSS 遵循小程序支持的样式能力和尺寸单位；保持布局在不同屏幕、字体缩放和安全区域下可用，不依赖浏览器专属 DOM/CSS 行为。
- 自定义组件通过 properties、data、methods、observers、生命周期和组件事件建立边界；父子组件通信优先使用明确的属性和事件，不直接修改父组件内部数据。
- 只有在项目确实需要并已验证兼容性时切换 `glass-easel` 或 Skyline。Skyline 与 `glass-easel` 存在配套依赖关系，配置前读取官方迁移和兼容性文档。

## 配置、网络与权限

- 修改 `app.json` 前确认页面路径真实存在且同名文件齐全；同步检查页面配置、tabBar、分包、预加载和组件声明。
- 网络请求使用官方 `wx.*` API 或项目已有封装。检查请求方法、超时、状态码、业务码、取消/重试策略和 loading/error/empty 状态。
- 小程序网络请求通常需要 HTTPS/WSS、合法服务器域名和有效证书；开发工具中的“跳过域名校验”只用于临时开发验证，不能作为上线方案。
- 需要用户授权的能力遵循最小权限和按需申请原则，在用户触发的明确场景解释用途；处理拒绝、取消、过期和设置页返回。
- 不在前端信任用户传入的身份、角色、价格、资源 ID 或权限字段。服务端必须重新鉴权和校验，防止平行越权与垂直越权。
- 平台能力、登录、支付、订阅、文件、位置、相机、蓝牙等接口属于高变化领域，先查官方 API 页面和对应合法性/权限要求。

## 性能、安全与验证

- 启动性能关注首屏体积、分包、首屏请求和资源加载；运行时性能关注长列表、频繁 `setData`、重复渲染、图片尺寸、动画和网络请求。
- 对长列表使用分页或增量加载，避免一次性渲染大量节点；图片按实际展示尺寸提供，必要时使用懒加载和占位状态。
- 不把安全控制实现为隐藏按钮或隐藏页面；客户端代码可被获取和分析，敏感逻辑必须放在受保护的后端。
- 不明文保存密码、密钥、身份证号、银行卡号等敏感数据；展示手机号、证件号等信息时做脱敏。
- 验证至少覆盖：首次进入、返回前台、网络失败、空数据、重复点击、权限拒绝、弱网、长文本、小屏设备和页面销毁后的异步回调。
- 开发者工具只代表调试环境；关键交互、布局、权限和网络行为以真实微信客户端和目标平台表现为准。

## 输出要求

完成代码任务时：

- 说明修改了哪些文件和用户可见行为。
- 对新增配置、最低基础库、权限、服务器域名或后端配合要求给出明确说明。
- 报告实际运行过的检查或测试；没有微信开发者工具/真机条件时，不声称已完成真机验证。
- 发现官方文档与现有项目实现不一致时，优先保护当前项目可运行性，并把兼容性差异和迁移建议写清楚。
